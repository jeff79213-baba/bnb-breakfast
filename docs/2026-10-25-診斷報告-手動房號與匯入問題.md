## 0. 給接手者的硬性約束

1. **不得改動資料結構**：`localStorage['rnb_data_v1']` 的 `rooms` / `daily` / `settings` 形狀不得變更，不得寫 migration，不得改 key 名稱。本次修復是純畫面層。
2. **不得清空或重寫客戶資料**：任何修復都不可呼叫 `clearRooms`、不可在載入失敗時自動覆寫。`loadState()` 失敗時目前回傳 `defaultState()`（記憶體空白），若接著有任何 `saveState()` 就會蓋掉原資料——修復時請不要製造這種路徑。
3. **`daily`（已用餐紀錄）不可動**：key 是「日期 → 房號 → 狀態」，與本問題無關，修好後勾選狀態必須原樣保留。
4. **只 add 明確檔案**，不要 `git add -A`（工作區有未追蹤的 xlsx / jpg / txt）。
5. **`sw.js` 的 `CACHE_NAME` 必須改版**，否則平板上看不到修復（現值 `bnb-breakfast-v22-color-stable`，見 [sw.js:2](../sw.js#L2)）。
6. 測試基準：`node --test` → **30/30 pass**（現況已實測通過；此數字會隨新增測試變動，改動後請重跑）。

## 1. 客戶症狀 vs 實際狀況

| 客戶說法 | 實際發生的事 |
|---|---|
| 「程式沒匯入資料」 | 資料有寫進 `localStorage`，但 `render()` 丟錯，畫面不更新；若是 CSV/TXT 匯入，連匯入視窗都不會關，看起來就像「按了沒反應」 |
| 「想手動增加房號，可是不行」 | 房號確實存進去了，但 `render()` 在 `renderGrid()` 就爆掉，後面的清空輸入框、`toast()`、`renderManageList()` 全部沒執行 → 畫面像壞掉、清單仍顯示「目前沒有房號」 |
| 「主頁一張卡片都沒有」 | 同上；空狀態畫面因為在 `renderGrid` 之前就顯示了，所以第一眼看起來「正常」 |

三句話總結：**資料進去 ≠ 畫面畫得出來**。這兩個客訴是**同一個 bug**。

## 2. 主因（A 級、必修）：`ReferenceError: rooms is not defined`

### 位置
- [app.js:573](../app.js#L573) `const html = rooms.map(r => {`
- [app.js:588](../app.js#L588) `if (rooms.length === 0 && state.rooms.length > 0) {`

兩處都在 `renderGrid()` 的「卡片模式」尾段（函式起點 [app.js:452](../app.js#L452)），但函式內**已經沒有宣告 `rooms`**。

### 成因（已用 git 追查）
```
git log -S "const rooms = filterRooms(tk" -- app.js
→ 6920c61 更新：房號與早餐 - 兩欄熟食/一般橫排+5欄統計+不加購改加購  (2026-08-23)
→ 404acaa 初始版本
```
2026-08-23 那次「兩欄熟食/一般」改版刪掉了 `const rooms = filterRooms(tk, currentFilter);`，但函式尾段仍在用 `rooms`。連帶後果：

- `filterRooms()`（[app.js:192](../app.js#L192)）變成死碼。
- 首頁的篩選 chips（全部／熱食／平台／未用餐／已用餐）從那天起就**完全失效**——點下去只會把 `currentFilter`（[app.js:18](../app.js#L18)）改掉再重畫，然後爆錯。
- `$('filterChips').classList.add('hidden')`（[app.js:248](../app.js#L248)）只在訂單模式／8 欄模式隱藏 chips，所以卡片模式下 chips 是可見的、而且按了會炸。

### 哪些操作一定會走到這條路

模式判斷是用「第一筆房間長什麼樣」猜的：

```js
// app.js:170
function isOrderMode()     { return state.rooms.length && state.rooms[0] && 'infant' in state.rooms[0]; }
// app.js:265
function isBreakfast8Mode(){ return state.rooms.length && state.rooms[0] && 'adult'  in state.rooms[0]; }
// renderGrid: 先 isOrderMode → renderOrderGrid；再 isBreakfast8Mode → 兩欄表格；否則卡片模式
```

| 進入卡片模式的情境 | 是否炸 |
|---|---|
| 0 筆房號（全新裝置）→ 之後手動新增 | 炸（且新增後的 `toast` 不會出現） |
| 手動新增房號（`addRoomsFromInput` 只寫 `{roomNumber, breakfastType}`，[app.js:766](../app.js#L766)） | 炸 |
| 匯入 CSV / TXT / 泛用格式（`confirmImport()` 的 else 分支只寫 `{roomNumber, breakfastType, orderId}`，[app.js:1163](../app.js#L1163)） | 炸，且**匯入視窗不會關閉** |
| 匯入 8 欄格式 | 不炸（走兩欄表格） |
| 匯入新訂單格式（I~M） | 不炸（走 `renderOrderGrid`） |

> 注意「匯入 CSV/TXT 也會炸」這件事：客戶若拿 CSV 或自家匯出的 txt 匯入，會看到「確認匯入按下去，視窗還在、畫面沒變」，**非常容易被理解成『檔案格式錯／沒匯入』**。

### 錯誤中斷順序（解釋「像完全沒反應」）
```js
// addRoomsFromInput() app.js:766
saveState();          // ← 資料先存好了
render();             // ← 這裡丟 ReferenceError
renderManageList();   // ← 沒執行（清單不更新）
$('newRoomInput').value = '';  // ← 沒執行（輸入框文字還在）
toast(`已新增 ${added} 間房號`); // ← 沒執行（沒有成功提示）
```
```js
// confirmImport() app.js:1163
saveState(); render(); closeModal('importModal'); importDraft = null;
$('fileInput').value = ''; toast(...);   // ← 全部沒執行
```

### 混合資料會讓情況更糟（重要）
由於模式判斷只看**第一筆**，一旦清單裡混進一筆手動房號：
- 排序 `sortRooms()` 會把它排到前面（例如 101），
- 它沒有 `adult` / `infant` 欄位 → 兩個判斷都 false → **整頁掉回卡片模式 → 原本匯入的 37 間全部消失**（重開也一樣，因為資料本身已混合）。

實測：8 欄 3 間 → 手動加 101 → 重載後 `#roomGrid` 子節點 0、統計仍顯示 3 間（統計在 `renderGrid` 之前算好，所以數字有動、下面空白，極具誤導性）。

### 已重現的環境
- 本機：`python -m http.server 8177`，匯入 `早餐102-512可視匯出.txt` 對應格式資料後手動加房 → console `app.js:573:16 Uncaught ReferenceError: rooms is not defined`
- 線上正式站：`https://jeff79213-baba.github.io/bnb-breakfast/` console 同樣 `app.js:573:16`（線上內容與 HEAD 一致，1671 行）→ **正式站現在就是壞的，不是只有某台平板。**

## 3. 次因（B 級）：Excel 解析器靠 CDN，離線／被擋就 100% 失敗

- [index.html:325](../index.html#L325) `<script src="https://cdn.jsdelivr.net/npm/xlsx@0.18.5/dist/xlsx.full.min.js">`
- [sw.js:3](../sw.js#L3) 的 `APP_SHELL` 只有同網域 8 個檔案，**跨網域不快取**；`fetch` 處理器也刻意只快取 `same origin`。
- [app.js:1058](../app.js#L1058)：`if (typeof XLSX === 'undefined') throw new Error('XLSX 未載入：請確認網路連線後重新整理')`，錯誤只以 4 秒 toast 呈現。

實測：把 `XLSX` 移除後匯入 → `❌ Excel 讀取失敗：XLSX 未載入：請確認網路連線後重新整理`。

→ 在「民宿現場、平板離線、或網路擋 jsdelivr」的情況下，**Excel 匯入結構上不可能成功**，只剩 CSV/TXT（而 CSV/TXT 會撞上第 2 節的 bug）。這與「離線優先 PWA」的宣稱矛盾，值得列為客戶「沒匯入」的第二大來源。

## 4. 次因（C 級、風險最高）：多工作表選錯，靜默覆蓋

[app.js:1057](../app.js#L1057) `parseExcelFile()` 的邏輯是「**掃所有工作表，第一個能解析出房號的就用**」：

```js
for (const name of wb.SheetNames) { ... if (po && po.rows.length) { parsed = po; break; } }   // 新訂單格式優先
// 否則：先找名稱含「早餐」的 sheet，再逐一遍歷其他 sheet，最後 fallback parseFromMatrix
```

**不是依「入住時間＝今天」挑表**。用客戶的 `02住客記錄 - 複製.xlsx`（80 個工作表）實測：

- 選到 `二館總表11411`
- 該表混了 **26 個不同入住日期**
- 產生 **163 筆「房號重複，以最後一筆為準」被靜默覆蓋**
- 最後「成功」匯入 **37 間** —— 但不是今天的名單

預覽視窗只會顯示「共判讀到 37 間」，沒有任何日期資訊，使用者無從察覺。這種「有匯入但內容不是今天」最難查，因為備料會照錯的人數算。

## 5. 次因（D 級）：格式不符時回饋太弱

- 8 欄格式要求：房號在 **B 欄**、必須 102–512 純數字、表頭要有「來源」「大人」（[app.js:966](../app.js#L966) `parseBreakfastMatrix`）。
- 新訂單格式要求：表頭含「房型房號」，在前 5 列內（[app.js:880](../app.js#L880) `parseOrderMatrix`）。
- 不符時只在 [app.js:1141](../app.js#L1141) 附近丟 4 秒 toast，沒有持久錯誤區、沒有 log、沒有「哪一列哪一欄不認識」的細節。

## 6. 次因（E 級）：系統自己匯出的檔案不能回灌

拿系統「匯出今日紀錄」的 `.txt`（如 `早餐102-512可視匯出.txt`）去匯入，實測失敗：

```
❌ 無法從檔案判讀出房號資料：第 2 列：「空白」無法判斷早餐種類，已略過
```

原因是匯出欄位是「房號／來源／住宿狀態／…」，而文字解析器（[app.js:831](../app.js#L831) `parseImport`）只認「房號＋早餐種類」。使用者很自然會以為「我自己匯出的當然能匯回去」。

**對照組（檔案本身沒壞）**：`5cNhxwZ3O0GKjaMrKXI26EdI2sjmbxogKuqoYbsW.xlsx`（單一工作表訂單格式）匯入正常，判讀 33 間；`02住客記錄 - 複製.xlsx` 的 xlsx 解析本身也正常（37 間）。所以問題在**選表與錯誤回饋**，不在解析器。

## 7. 就算修好當機，「手動新增」功能本身仍不足

- 手動房只有「房號 + 早餐種類」；[app.js:1651](../app.js#L1651) `openRoomModal()` 只能改種類，**沒有來源／大人／小孩／嬰幼兒／用餐時間的輸入入口**。
- 這系統的價值就是人數與用餐時段；手動房在結構上無法貢獻備料統計（`calcPrepTotals()` 把它當 0 人，見 [app.js:1198](../app.js#L1198)）。
- 手動房是另一種資料形狀（沒有 `adult` / `infant`），與匯入後的兩欄模式是兩套東西，**混用必出問題**（見第 2 節「混合資料」）。

→ 如果只補回 `const rooms = ...` 而不處理形狀問題，會出現新客訴：**「房間有出現，但備料少算一份」**。這比現在完全不能用更難解釋。

## 8. 建議修復方案（分級，勿一次全上）

### A 級：必做，資料零風險（估 30 分鐘含驗證）

1. `renderGrid()` 卡片模式補回資料來源，例如在 `grid.style.display = ''` 之後：
   ```js
   const rooms = filterRooms(tk, currentFilter);
   ```
   （`filterRooms` 已存在、已 export 到 `core.js` 的用法請一併確認；回傳已 `sortRooms`。）
2. 把模式判斷從「看第一筆」改成「看全部」，避免混合資料整頁翻車：
   ```js
   function isOrderMode()     { return state.rooms.length > 0 && state.rooms.every(r => 'infant' in r); }
   function isBreakfast8Mode(){ return state.rooms.length > 0 && state.rooms.every(r => 'adult'  in r); }
   ```
   **注意**：改成 `every` 之後，「匯入 8 欄 + 手動加一間」會掉回卡片模式（37 間變卡片，而不是兩欄表）。若不能接受，改法 B 是「`some` 就進該模式 + 在新增時把新房間補齊欄位」，見第 3 點。請與使用者確認要哪一種，這是行為選擇題，不是純 bug fix。
3. `addRoomsFromInput()` 依現有資料形狀補欄位（**只影響新加入的房號，不動舊資料**）：
   - 若現有資料是 8 欄形狀 → 新房間帶 `adult:0, child:0, mealTime:'', source:'手動', status:'', eggMilk:'', vegan:''`
   - 若是新訂單形狀 → 再帶 `infant:0`
   - 卡片形狀 → 維持現狀
   這樣手動房才會被備料統計與兩欄表正確處理。
4. `confirmImport()` 的成功 toast 與 `closeModal` 應放在 `render()` 之前或 `try/finally` 內，避免再次出現「錯誤 → 視窗不關」的誤導（防禦性，非 bug 本體）。
5. `sw.js` `CACHE_NAME` 改版（例如 `bnb-breakfast-v23-manual-room-fix`）。
6. 若決定讓 chips 恢復作用，`currentFilter` 在「切換模式／匯入完成／新增房號」後重置為 `'all'`，避免使用者停在 `hot` 或 `hot-pending` 而以為房間不見了。
7. **一致性提醒**：8 欄表格的「熟食／平台」分類用的是 `core.js` 的 `isHotMeal()` / `isAddon()`（來源導向），而 `filterRooms()` 用的是 `r.breakfastType === 'hot'`。兩者語意不同；若將來要在 8 欄模式顯示 chips，必須改用 `isHotMeal`，否則篩選結果會與畫面上「熟食」標頭不一致。

### B 級：建議做，需挑平板可連網的時段上線

- 把 `xlsx.full.min.js`（v0.18.5）放進專案（例如 `vendor/`），改 [index.html:325](../index.html#L325) 為本機路徑，並加入 `sw.js` 的 `APP_SHELL`。
- 只換「從哪載入解析器」，**不動任何資料邏輯**。
- 上線後每台平板需連網開一次才會取得新 SW。

### C 級：暫緩，會改變「匯進來的內容」

- 依「入住時間＝今天」挑工作表；重複房號改為警告清單而非靜默覆蓋。
- **這是真正會影響營運的修改**（改的是匯入結果，選錯規則會導致某天早上人數不符）。
- 折衷建議：先在預覽視窗列出「偵測到的入住日期清單 + 重複房號筆數」，不改自動選擇；觀察一個旺季週期再談自動挑表。

### 明確不建議
- 不要為了解決畫面問題而去改 `localStorage` 結構或加 migration。
- 不要「順手」重構 `renderGrid`（該函式已混了兩種模式，重構風險遠大於 2 行修復）。
- 不要把 `renderOrderGrid` / 8 欄表格的分組配色邏輯動到（`96c7937` 才剛修好）。

## 10. 客戶端現況處置（給客服／現場的指示）

**可以說**：「資料還在，是顯示的問題，等更新後會自己回來，不用重新輸入。」

**絕對不要做**：
- ❌ 清除網站資料 / 清除瀏覽器資料 / 無痕模式開（會把 `localStorage` 清掉，那就真的沒了）
- ❌ 移除主畫面圖示後重加（部分環境會清站台資料）
- ❌ 重新匯入並按「確認匯入」（`confirmImport()` 會 `state.rooms = ...` 整批取代，在修好前若同時有手動資料會更亂）

**可先做的檢查**（Safari 需接 Mac 或使用遠端檢查；Chrome/Edge 可在平板外接鍵盤用 `chrome://inspect` 取得 console）：
```js
const s = JSON.parse(localStorage.getItem('rnb_data_v1'));
console.log({
  房數: s.rooms.length,
  第一筆欄位: Object.keys(s.rooms[0] || {}),
  有紀錄的日期數: Object.keys(s.daily || {}).length,
  今天: s.daily?.[new Date().toLocaleDateString('sv')]
});
```
