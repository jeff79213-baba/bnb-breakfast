# 用餐時間排序 — 設計文件

**日期：** 2026-10-18
**狀態：** 已核准（方案 A）
**前置：** 「按姓名分類」（`state.settings.sortMode` = `'room'|'name'`）已完成

## 需求

訂單模式的排序開關目前有「房號 / 姓名」兩顆按鈕，新增第三顆「用餐時間」：
- 有用餐時間的房依時間 **早→晚** 排在前面
- 無用餐時間（空白、`不用餐`、格式無效）的房排最後
- 其他功能（蛇形兩欄、熟食/平台分區、typebar、統計、橫幅）完全不變
- 僅訂單模式顯示開關（8 欄模式不變）

## 決策

| 項目 | 決定 |
|------|------|
| 排序值 | `state.settings.sortMode` 擴為 `'room' \| 'name' \| 'time'`，預設 `'room'` |
| 排序邏輯位置 | `core.js` 新增純函式 `sortRoomsByMealTime(list)`，可單測 |
| 時間解析 | 沿用既有 `core.js:103 timeOf(label)`（regex `^(\d{1,2}):(\d{2})$`，h 1~12、min%5===0） |
| `不用餐` | `timeOf('不用餐')` 回傳 `null` → 歸入「無時間」組，排最後 |
| 同時間併列 | 依房號小→大（`roomNumberCmp`） |
| 無時間組內排序 | 依房號小→大 |
| 穩定性 | 完全同鍵者維持原相對順序（`Array.prototype.sort` 在本專案引擎為穩定排序） |
| 不修改輸入 | `list.slice()` 後排序，回傳新陣列 |

## 改動點

### `core.js`
1. 於 `sortRoomsGrouped` 函式結束後、`clearRooms` 之前新增 `sortRoomsByMealTime(list)`
2. `return { ... }` 加入 `sortRoomsByMealTime`

```js
  function sortRoomsByMealTime(list) {
    const rooms = (list || []).slice();
    rooms.sort((x, y) => {
      const tx = timeOf(x && x.mealTime), ty = timeOf(y && y.mealTime);
      if (tx && ty) {
        const d = tx.h - ty.h || tx.m - ty.m;
        if (d !== 0) return d;
      } else if (tx) return -1;
      else if (ty) return 1;
      return roomNumberCmp(roomKeyOf(x), roomKeyOf(y));
    });
    return rooms;
  }
```

- 有時間者依 `h`/`m` 升冪；同時間或皆無時間 → `roomNumberCmp`
- `tx`/`ty` 皆 truthy 且 `d === 0` 時也落到 `roomNumberCmp`，保證同時間依房號
- 「皆無時間」時 `tx`/`ty` 皆 falsy，直接落到 `roomNumberCmp`，無時間組內依房號

## 測試策略

### core 測試（node:test）
1. 依時間早→晚排序
2. 無時間／空白／`不用餐` 殿後，且該組內依房號
3. 同時間併列依房號
4. 空輸入／`undefined` 回傳 `[]`
5. 不修改原陣列
6. 無效時間格式（如 `'9:7'`、`'13:00'`、`'08:3'`）視為無時間

### 手動瀏覽器驗證
1. 匯入訂單模式資料 → 切「用餐時間」→ 兩欄內由早到晚，無時間房在各自分區末尾
2. 切回「房號」／「姓名」→ 行為與改動前一致
3. `不用餐` 房排在該分區最後
4. 8 欄模式無排序開關，行為不變
5. 重整頁面 → 排序選擇保留
6. 熱食/平台分區、typebar、統計、橫幅不受影響
7. 320px 寬度版面不跑版
