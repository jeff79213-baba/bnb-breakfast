# 房號與早餐 — 熟食人數統計（橫幅第二行）設計

日期：2026-09-26
專案：房號與早餐（`app.js` / `index.html` / `core.js` / `style.css` / `sw.js`）

## 背景與動機

目前主頁面頂部有一條橘色橫幅「尚有 N 間熟食未用餐」，只顯示**房間數**。廚房作業真正需要的是**人數**（要做幾份餐、幾大幾小）。使用者要求在橫幅旁加上：

1. 熟食總人數 = 大人 + 小孩
2. 未食用總人數 = 大人 / 小孩

## 現況（探索結果）

- 橫幅：`index.html:65` 的 `<button id="hotAlertBanner" class="hot-banner hidden">`，內容由 `app.js:224-233` 以 `banner.textContent = ...` 寫入
- 房間數來源：`core.js:45 computeHotPending(rooms, statusOf)`，內含兩道篩選
  - `core.js:30 isHotRoom(r)` 判定熟食（看 `source` 含 手動訂單/官網/官網訂單、或 `vegan`/`eggMilk` 為加購；`vegan === '不加購'` 則排除）
  - `core.js:41 isNoMeal(r)` 排除 `mealTime === '不用餐'`
  - 狀態非 `completed` 才計入
- 橫幅的三種狀態：
  - `alert`（橘底、pulse 動畫）：`尚有 N 間熟食未用餐`
  - `ok`（綠底）：`熟食已全數用餐完成`
  - `ok`（綠底）：`今日尚無熟食房號`
- 點擊行為：`app.js:1371-1373`，僅在 `alert` 狀態下觸發 `currentFilter = 'hot-pending'`
- 人數欄位（`app.js:102-107` sanitize 決定資料模式）
  - 新訂單模式：`adult` / `child` / `infant`（三欄）
  - 8 欄模式：`adult` / `child`（兩欄）
  - 舊純房號模式：無任何人數欄位
- 既有「小孩」定義：`app.js:186 orderKid(r) = child + infant`；備料區 `app.js:1213` 的 `kid = C + I` 兩處一致
- 既有 CSS：`style.css:97-116` `.hot-banner`（單行置中、19px/800、padding 16px）

### 已知的既有口徑不一致（本次不處理）

- `app.js:200` 篩選 `hot-pending` 與 `app.js:1192` 備料區都用 `r.breakfastType === 'hot'` 判定熟食，與橫幅的 `isHotRoom()` 不同。也就是說橫幅顯示「尚有 3 間」但點進去可能看到不同數量的房。
- 本設計**只求新的人數與橫幅既有的間數一致**（同用 `isHotRoom()`），不順手統一上述兩處，避免擴大範圍。

## 目標

1. 橫幅上同時顯示熟食總人數（大人／小孩）與未食用人數（大人／小孩）
2. 已用餐的房間，其大人與小孩人數一併扣除
3. 不新增任何 UI 區塊，只改橫幅本身（橫幅內變兩行）
4. 橫幅的點擊範圍、`pulse` 動畫、篩選行為完全不變

## 設計

### A. 計算邏輯 — `core.js` 新增純函式 `computeHotPeople(rooms, statusOf)`

回傳結構：

```js
{
  total:   { adult, kid, people },   // 全部熟食房（已排除不用餐）
  pending: { adult, kid, people }    // 其中狀態非 completed 的
}
```

規則（每一條都與 `computeHotPending` 對齊）：

| 項目 | 規則 |
|---|---|
| 熟食 | `isHotRoom(r)` |
| 排除 | `isNoMeal(r)`（`mealTime === '不用餐'`） |
| 大人 | `Number(r.adult) \|\| 0` |
| 小孩 | `(Number(r.child) \|\| 0) + (Number(r.infant) \|\| 0)` |
| 未用餐 | `statusOf(r) !== 'completed'`，整間房的大人小孩一起扣 |

- 舊純房號模式（無 `adult`/`child`/`infant`）自然算出 0，不需特殊處理
- 空／`undefined` 輸入回傳全 0 結構
- 在 `core.js` 的 `return {}` 物件中一併 export

### B. 版面 — 橫幅改兩行

手機 390px 實測尺寸：橫幅可用寬度約 334px。19px 粗體的「尚有 3 間熟食未用餐」已佔約一半寬度，兩組數字無法塞進同一行（12px 需約 364px，會爆版），因此採**橫幅內兩行**。

```
╔══════════════════════════════╗
║     尚有 3 間熟食未用餐      ║  ← 主行 19px / 800（維持原樣）
║ 熟食 8 人（大人5 小孩3）　未食用 3 人（大人2 小孩1）  ║  ← 次行 12px / 600
╚══════════════════════════════╝
```

- `index.html` 的 `hotAlertBanner` **維持空元素**，內容仍由 `app.js` 寫入（只改寫入的結構，不改成靜態 HTML）
- `app.js` 改用 `innerHTML` 寫入兩個 span：
  - `<span class="hot-banner-main">` — 主警示文字，字級與現有 `.hot-banner` 相同
  - `<span class="hot-banner-sub">` — 次行，同一行內並列兩組人數
- 次行文字格式：`熟食 N 人（大人A 小孩B）　未食用 M 人（大人C 小孩D）`（中間用全形空白分隔，不加分隔線以免視覺雜訊）
- 12px 下次行約需 290px，390px 螢幕（可用 334px）可容納；320px 螢幕（可用 264px）會超出，因此 `.hot-banner-sub` **不設 `white-space:nowrap`**，允許自然換行成兩行，避免溢出
- `style.css` 修改：`.hot-banner` 改為 `display:flex; flex-direction:column; align-items:center; gap:4px;`，並把 `font-size`/`font-weight` 從 `.hot-banner` 移到 `.hot-banner-main`；新增 `.hot-banner-sub`
- 390px 下橫幅高度約 54px → 78px；點擊範圍不變（仍是整條 button）

### C. 三種狀態的呈現

| 狀態 | 主行 | 次行 |
|---|---|---|
| 有未用餐熟食 | `尚有 N 間熟食未用餐` | 顯示兩組人數 |
| 熟食全數用餐完成 | `熟食已全數用餐完成` | 顯示兩組人數（未食用為 0） |
| 今日尚無熟食房號 | `今日尚無熟食房號` | **不顯示次行** |
| 有熟食房但人數全為 0（舊純房號模式） | 依上方規則 | **不顯示次行** |

- 「不顯示次行」的實作：當 `total.people === 0` 時，只寫入 `hot-banner-main`，不寫入 `hot-banner-sub`
- 判斷條件為 `total.people === 0`，同時涵蓋「沒有熟食房」與「有熟食房但沒人數欄位」兩種情況，不需分別判斷

### D. 渲染整合

`app.js render()` 內，現有 `app.js:225` 算 `hotPending` 的地方一併算 `hotPeople`：

```js
const hotPeople = C.computeHotPeople(state.rooms, r => getStatus(tk, r.roomNumber));
```

之後依 C 節的三種狀態組合出主行／次行文字。

`computeHotPending`（`app.js:225`）的呼叫**維持不動**：主行的房間數 `N` 仍由它提供，本次不拿 `computeHotPeople` 取代它，兩者規則一致但各自獨立、變動風險最小。

## 手動驗證

1. 匯入訂單模式資料（I~M 欄），確認橫幅第二行顯示 `熟食 N 人（大人A 小孩B）　未食用 M 人（大人C 小孩D）`
2. 點掉一間房的用餐狀態 → 確認該房大人小孩從「未食用」扣除、「熟食」總數不變，間數同步減 1
3. 全部用餐完成 → 橫幅轉綠底，次行顯示 `未食用 0 人（大人0 小孩0）`
4. 匯入 8 欄模式資料（有 adult/child 無 infant）→ 確認小孩數字正確
5. 用舊純房號資料 → 確認橫幅不出現次行
6. 點橫幅 → 篩選行為與點擊範圍與改動前一致
7. 390px 寬度確認次行單行顯示；320px 寬度確認次行自然換行且不溢出、不裁切
