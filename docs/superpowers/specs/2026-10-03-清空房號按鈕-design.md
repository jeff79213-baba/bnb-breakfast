# 房號與早餐 — 設定欄「清空房號」按鈕設計

日期：2026-10-03
專案：房號與早餐（`app.js` / `index.html` / `core.js` / `style.css` / `sw.js`）

## 背景與動機

每日客房退房後，需要把上一批的房號清單清掉，再匯入新一天的訂單。目前沒有任何「整批清空」的入口，只能逐間在「管理房號」裡刪，或用匯入 0 筆的方式取代。使用者要求在設定欄（功能選單）加一個清空鍵。

## 現況（探索結果）

- **設定欄 = 功能選單 modal**：`index.html:93-104`，`#menuModal` 內依序為
  `#menuManageBtn`（管理房號）、`#menuImportBtn`（匯入資料）、`#menuPrepBtn`（備料區）、
  `#menuSlotsBtn`（早餐用餐時間）、`#menuExportBtn`（匯出今日紀錄）、`#menuCloseBtn`（關閉）
- **資料結構**：`app.js:47-59` `defaultState()` 回傳
  `{ version, settings: { types, prep, mealSlots, sortMode }, rooms: [], daily: {} }`
- **儲存**：`app.js:10` `STORAGE_KEY = 'rnb_data_v1'`；`app.js:86-93` `saveState()` 寫入 `localStorage`
- **既有「取代房號清單」行為**：匯入預覽 modal 已宣告「⚠️ 匯入會取代現有的房號清單（用餐紀錄保留）」
  （`index.html:129`），實作於 `app.js:1162-1186`（`confirmImport()` 直接覆寫 `state.rooms`，不動 `settings` 與 `daily`）
- **空狀態**：`app.js:246` `render()` 內 `$('emptyState').classList.toggle('hidden', !empty)`，房號為 0 時自動顯示空白畫面
- **modal 開關**：`app.js:610-611` `openModal(id)` / `closeModal(id)`
- **現成 CSS**：`style.css:222` `.btn.danger`、`style.css:223` `.btn.subtle`、`style.css:227` `.row-actions`
- **測試現況**：`tests/core.test.js` 只測 `core.js` 的純函式（`node:test`，21 個案例）

## 目標

1. 功能選單新增「🗑️ 清空房號」入口
2. 清空 `rooms`，但**完整保留** `settings`（備料比例、餐別、時段、排序）與 `daily`（所有用餐紀錄）
3. 需二次確認，且確認畫面要顯示即將清空的房號數量
4. 清空後畫面回到空白狀態，可直接重新匯入

## 範圍外的項目

- 不清空／不重設任何設定（已與使用者確認：備料比例等要保留）
- 不動 `daily`（過往用餐紀錄保留，與既有匯入行為一致）
- 不做「 undo 復原」或清空前自動備份（房號可由 Excel 重新匯入，無永久遺失風險）
- 不做全選／反選等批次操作（既有「管理房號」已提供逐間刪除）
- 不改「管理房號」modal、不改主頁面版面

## 設計

### A. 純函式 — `core.js` 新增 `clearRooms(state)`

```js
function clearRooms(state) {
  return Object.assign({}, state, { rooms: [] });
}
```

- 回傳新物件（淺拷貝），`settings` 與 `daily` 以引用原樣帶入，**不被修改也不被清空**
- 放在 `core.js` 而非 `app.js`，理由：沿用本專案「`core.js` 放純函式並由 `node:test` 測試」的既有分層，
  讓「設定與紀錄必須保留」這個關鍵行為有自動化測試把關
- 於 `core.js:166-171` 的 `return {}` 一併 export

### C. 行為 — `app.js`

新增兩個 handler 與一個渲染函式：

```js
function openClearConfirm() {
  $('clearSummary').innerHTML = `將清空目前 <b>${state.rooms.length}</b> 間房號。`;
  openModal('clearModal');
}

function doClearRooms() {
  const n = state.rooms.length;
  state = C.clearRooms(state);
  saveState();
  closeModal('clearModal');
  closeModal('menuModal');
  render();
  toast(`🗑️ 已清空 ${n} 間房號`);
}
```

事件綁定（加在 `app.js:1390` 附近既有的選單綁定區）：

| 元素 | 行為 |
|---|---|
| `#menuClearBtn` | `closeModal('menuModal')` → `openClearConfirm()` |
| `#clearCancelBtn` | `closeModal('clearModal')`（不動資料） |
| `#clearConfirmBtn` | `doClearRooms()` |

設計決策：

- 點「清空房號」時**同時關閉功能選單**，讓確認 modal 不被選單 backdrop 蓋住（與 `app.js:1391`
  `menuManageBtn` 關閉選單再開另一個 modal 的既有做法一致）
- `render()` 會自行把 `#emptyState` 顯示出來（`app.js:246`），不需額外處理
- `toast` 沿用現有函式（`app.js:601`）
- 房號已為 0 時仍可點（無害），確認句顯示「將清空目前 0 間房號。」；不額外禁用按鈕以免增加狀態複雜度

### D. 邊界情況

| 情況 | 行為 |
|---|---|
| `state.rooms` 已為空 | 清空後仍為空，`toast` 顯示「已清空 0 間房號」，無錯誤 |
| 房號為 0 | `#menuClearBtn` 仍可點，流程正常走完 |
| 清空前有未儲存的 modal（如房號編輯） | 不會發生：清空入口在功能選單內，modal 為單一開啟 |
| `daily` 留下舊房號紀錄 | 無害。`daily` 以「日期 → 房號」為 key，舊房號不會被新匯入資料用到；與既有匯入保留 `daily` 的行為一致 |
| `state` 為 `null` | 不可能。`loadState()`（`app.js:61`）保證回傳物件 |

## 測試策略

`tests/core.test.js` 新增 `clearRooms` 案例（沿用現有 `node:test` 風格）：

1. 基本：清空後 `rooms` 為 `[]`
2. **關鍵**：`settings`（含 `prep` 內的係數、`types`、`mealSlots`、`sortMode`）與清空前深度相等
3. **關鍵**：`daily` 與清空前深度相等
4. 不 mutate 原始物件：傳入的 `state.rooms` 仍為原本長度
5. 邊界：`rooms` 本來就是 `[]` 時回傳 `rooms: []`

執行方式：`node --test tests\core.test.js`（既有 21 個測試須全數通過）。

## 手動驗證

1. 匯入一份訂單資料 → 選單 → 點「🗑️ 清空房號」→ 確認畫面顯示正確的房號數量
2. 點「確定清空」→ 主頁面回到空白狀態、`toast` 顯示「已清空 N 間房號」
3. 重新整理頁面 → 房號仍為空（已寫入 `localStorage`）
4. 重新匯入 → 房號恢復；**確認備料區的係數沒被重設**（重點：果凍 1.1、蛋 1.5、飯量 0.2/0.1 等）
5. 選單 →「早餐用餐時間」→ 確認已設定的時段仍在
6. 選單 → 點「取消」→ 資料完全沒變
7. 備料區確認：若有勾選「已完成」的房，清空後 `daily` 紀錄未被移除（下次匯入同房號時狀態仍在，
   這是保留 `daily` 的既有行為，非本次新增）
