# 房號與早餐 — 按姓名分類（訂單模式）設計

日期：2026-09-23
專案：房號與早餐（`app.js` / `index.html` / `core.js` / `style.css`）

## 背景與動機

訂單模式下（I~M 欄，含顧客/姓名欄位），同一人可能訂多間房（如 305/308/502 同屬一人）。目前版面依房號排序，同一人的房可能被其他房號打散。希望在維持整體蛇形兩欄分佈不變的前提下，可選擇「按姓名分組」讓同一人的房排在一起。

## 現況（探索結果）

- 訂單模式渲染：`renderOrderGrid(tk)`（app.js:316）
  - `all = sortRooms(state.rooms)`（依房號小→大，app.js:146）
  - `hotList = all.filter(C.isHotRoom)`、`normalList = all.filter(r => C.isPlatformRoom(r))`
  - `ordered = hotList.concat(normalList)`，`split = ceil(ordered.length / 2)`
  - 左欄 `ordered.slice(0, split)`、右欄 `ordered.slice(split)`（蛇形：左欄排滿才接右欄）
- 姓名欄位：`guestName`（app.js:902 匯入時讀入；app.js:103 sanitize 保留；app.js:334/452 顯示於房號旁）
- 8 欄模式（早餐102-512）無姓名欄位，不在本功能範圍
- 頂部統計區：`statHot`／`statNormal` 五宮格等（index.html:32 起），無排序控制項

## 目標

1. 訂單模式新增「排序方式」開關：**房號**（預設）／**姓名**
2. 姓名模式：熟食區、平台區各自內部，同一 `guestName` 的房相鄰排列
3. 維持整體蛇形兩欄分佈、熟食在前平台接續的分區結構完全不變
4. 開關選擇持久化（`localStorage`），重整後保留

## 設計

### A. 排序方式開關（UI）

- 位置：頂部統計區（五宮格）旁，新增一組切換按鈕（房號｜姓名），小尺寸樣式與現有色調一致
- 預設值：房號
- 儲存：`state.settings.sortMode`（值 `'room' | 'name'`），隨 `saveState()` 存 localStorage（key `rnb_data_v1`），重整後保留。詳見 D 節
- 訂單模式顯示此開關；8 欄模式與舊卡片模式不顯示

### B. 姓名分組排序規則（純函式）

在 `core.js` 新增 `sortRoomsGrouped(list)`：

對傳入列表（呼叫端已先分好熟食/平台區塊）：

1. 將房間依 `guestName` 分組：
   - 有姓名（trim 後非空）的房：依姓名分組
   - 無姓名（空）的房：獨立放為一區，永遠排在最後
2. **組間順序**：依「各組內最小房號」小→大排列
3. **組內順序**：依房號小→大
4. 無姓名區：依房號小→大

房號比較沿用現有 `numericAwareSort`（core 內需有等價實作或從 app 傳入 comparator）。為維持 core 純函式獨立，於 core.js 內新增純 comparator（與 app.js`numericAwareSort` 相同邏輯）。

### C. 渲染整合

`renderOrderGrid`（app.js:316）改為：

```js
const byRoom = sortRooms(state.rooms);                    // app.js 既有函式（依房號）
const all = state.settings.sortMode === 'name'
  ? C.sortRoomsGrouped(byRoom)                             // 依姓名分組
  : byRoom;
```

之後的 `hotList`／`normalList`／`ordered`／`split`／兩欄輸出邏輯**完全不動**。

決定：先 `sortRooms`（房號序）再 `sortRoomsGrouped`。原因：分組的「組間依最小房號」與「組內依房號」皆以房號為基準，先排好房號再分組可保證組間/組內順序正確，且同名組的回填順序穩定。`sortRooms` 沿用 app.js 既有函式；`sortRoomsGrouped` 內部的房號比較用 core 自己的 comparator。

### D. 資料持久化（settings）

- `state.settings.sortMode`（`'room' | 'name'`）以預設 `'room'`，隨 `saveState()` 存入 `localStorage`（key `rnb_data_v1`），重整後保留
- 同時保留獨立 key `rnb_sortMode` 亦可行，但為與既有 state 持久化一致，建置於 `state.settings.sortMode` 內即可
- `loadState()`（app.js:60）需在 settings 合併時帶入預設

決定採 `state.settings.sortMode`，與 `defaultState()` 的 `settings` 合併邏輯一致，無需額外 localStorage key。

### E. 開關的顯示控制

- 訂單模式（`isOrderMode()`）時顯示開關；其他模式隱藏
- `render()` 內在五宮格渲染後追加開關切換（或於 HTML 靜態放置、依模式控制顯隱）

## 範圍外的項目

- 不變動 8 欄模式（早餐102-512）排序
- 不變動蛇形分欄的 `split` 計算與左右分配邏輯
- 不變動舊卡片模式
- 不做跨熟食/平台欄的合併（同一人跨欄時，各自在熟食區、平台區內分組，不跨欄合併）

## 測試策略

`tests/core.test.js` 新增：

1. `sortRoomsGrouped`：同姓名相鄰（例 305/308/502 同名 → 輸出一組、中間無其他房）
2. `sortRoomsGrouped`：組間依各組最小房號排（組 A 最小房小於組 B → A 在前）
3. `sortRoomsGrouped`：組內依房號小→大
4. `sortRoomsGrouped`：無姓名房排最後（依房號）
5. `sortRoomsGrouped`：混合案例（多組 + 無姓名）一次驗證

執行方式：`node --test tests\core.test.js`（既有 11 個測試須全數通過）。

## 手動驗證

1. 訂單模式匯入含姓名的檔案
2. 切「姓名」→ 確認同一人房相鄰、無姓名房在區塊後段
3. 切「房號」→ 回到原本依房號排序
4. 重整頁面 → 開關狀態保留
5. 8 欄模式確認開關不出現、排序如舊
