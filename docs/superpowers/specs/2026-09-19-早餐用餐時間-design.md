# 早餐用餐時間選項 — 設計文件

日期：2026-09-19
專案：房號與早餐（民宿早餐房號管理系統）
基準：已提交版本（含新訂單模式 + 備料區）

## 背景

店家希望「早餐用餐時間」可自己維護選項，並在主頁面快速指派到每一房。

## 需求

1. 設定區新增「早餐用餐時間」：店家自行新增時段（例：8:15、8:30、9:00、9:30），並以勾選啟用；啟用狀態**常駐**，不需每日重選。
2. 勾選啟用的時段顯示在主頁面時間欄的「更改欄」供選擇。
3. 檔案匯入時時間欄為空白先行，店家再逐房選擇時段，或選「不用餐」。
4. 被標為「不用餐」的**熟食房**，不計入主頁頂部「尚有 X 間熟食未用餐」。

## 資料結構

### settings.mealSlots（新增，localStorage `rnb_data_v1`）

```js
settings: {
  types: [...],               // 既有
  prep: {...},                // 既有（備料區）
  mealSlots: [                // 新增
    { label: '8:15', enabled: true },
    { label: '8:30', enabled: true }
  ]
}
```

- 預設為空陣列 `[]`。
- `label`：時段文字，店家輸入的原樣。
- `enabled`：勾選啟用（常駐），只有 enabled 的時段出現在時間選擇彈窗。
- 新增/刪除/勾選都存回 `state.settings.mealSlots`，重繪設定列表。

### 房間 mealTime（沿用既有欄位）

- 每房 `mealTime` 沿用現有字串欄位。
- 選「不用餐」→ `mealTime = '不用餐'`。
- 匯入邏輯不變：新訂單模式匯入 `mealTime:''`；8 欄模式沿用檔案內的用餐時間。

## UI 設計

### 設定區「早餐用餐時間」（新選單按鈕 + 新 modal）

- 功能選單新增按鈕：`🍳 早餐用餐時間`（放在備料區下方）。
- 開啟 `mealSlotsModal`（sheet）：
  - 標題：早餐用餐時間
  - 輸入框（text，placeholder「例如 8:15」）＋「新增」按鈕
  - 時段列表：每筆一個 checkbox（啟用）＋ 時段文字 ＋ 刪除鈕（✕）
  - 空列表時顯示提示「尚未設定時段」
  - 「完成」關閉
- 新增時過濾重複與空白。

### 主頁面時間欄（更改欄）

- 新訂單模式與 8 欄模式的網格中，時間格改為可點（`data-timeset`）。
- 點時間格 → 開啟 `timePickerModal`（sheet）：
  - 標題：房號 XXX 用餐時間
  - 按鈕區：所有 `enabled` 的時段（每個一格大按鈕）
  - 「不用餐」按鈕（獨立樣式，例如灰色）
  - 「清除（空白）」按鈕
  - 取消可點遮罩或關閉鈕
- 選定後：`room.mealTime = 所選值`（不含「清除」則存 `''`），`saveState()`、`renderGrid(tk)`、toast。
- 若無任何啟用時段：顯示提示「尚未設定時段，請先到選單設定」＋仍提供「不用餐」「清除」。
- 時間格須 `stopPropagation`，不觸發整列切換用餐狀態。
- 新訂單模式的「改」按鈕（開啟完整 orderEditModal）保留不動，其內的用餐時間輸入框亦保留；兩者可並行。

## 統計修正

- `render()` 的熟食警示橫幅（`hotAlertBanner`）：
  - 新訂單模式：`orderInHot(r) && !orderIsAddon(r) && pending && r.mealTime !== '不用餐'`
  - 8 欄模式：`isHotMeal(r) && pending && r.mealTime !== '不用餐'`
  - 卡片模式：`breakfastType === 'hot' && pending && r.mealTime !== '不用餐'`
- 其餘統計（熟食/一般/加購/已/未用餐）不變。

## 不改動的範圍

- 備料區、匯出、匯入、加購/改回邏輯
- 卡片模式（無時間欄）
- Firebase 集合／localStorage 前綴（沿用 `rnb_`）

## 測試策略

- 設計為純前端 vanilla，無現成測試框架。
- 抽離時段相關純函式（啟用清單、新增去重、不用餐判定）後，以 Node 內建 `node:test` 撰寫單元測試。
- DOM 互動（彈窗點選）採手動驗證清單。
