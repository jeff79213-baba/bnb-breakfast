# 房號與早餐 — 分類/平台改名/訂單分色/用餐時間 設計

日期：2026-09-19
專案：房號與早餐（民宿早餐房號管理系統）
基準：已提交版本（含新訂單模式 + 備料區），工作區已還原。
本文件合併並取代 `2026-09-19-breakfast-room-category-order-design.md`（舊設計的 E「每日勾選」由本次「常駐勾選」取代）。

## 需求總覽

1. **分類規則**：熟食以「訂單來源＋加購」判別，不再依戀大人/小孩欄位（短租房不再誤判熟食）。
2. **標題改名**：右欄「一般」→「平台」。
3. **訂單編號反查與分色**：匯入時從同檔訂單 sheet 反查訂單編號，同一筆訂單的多間房用同色底線標示，跨熟食/平台兩欄連貫。
4. **早餐用餐時間**：設定區維護時段清單＋常駐勾選啟用；主頁面時間欄可點擊選擇（時段／不用餐／清除）；匯入時時間欄空白。
5. **統計修正**：被標「不用餐」的熟食房不計入「尚有 X 間熟食未用餐」。

## A. 分類規則（兩個模式統一）

```
不加購（vegan === '不加購'）      → 平台（右欄）
加購（eggMilk 含『加購』）        → 熟食（左欄）
來源 = 手動訂單 / 官網 / 官網訂單  → 熟食（左欄）
其餘（Booking/Agoda/CTrip/短租等） → 平台（右欄）
```

- `IS_HOT_SOURCE = ['手動訂單', '官網', '官網訂單']`（比對時採包含文字，沿用現行 `/手動|官網/`）
- 新增純函式（放 `core.js`）：
  - `isHotSource(src)`：來源是否熟食來源
  - `isAddon(r)`：`eggMilk` 是否加購
  - `isHotRoom(r)` = `!isNoAdd(r) && (isAddon(r) || isHotSource(r.source))`
  - `isPlatformRoom(r)` = `!isHotRoom(r)`
  - `isNoAdd(r)` = `r.vegan === '不加購'`
- **取代**現有的 `orderInHot` / `orderIsNoAdd` / `isHotMeal` / `isNormalMeal` 於網格、統計、警示橫幅的使用。
- 短租房（312/507/512 等）來源非手動/官網 → 自動歸平台。

## B. 標題改名

- 網格右欄標題「一般」→「平台」（新訂單模式 `renderOrderGrid` 與 8 欄模式 `renderGrid` 兩處）。
- 空狀態「無一般」→「無平台」（兩處）。

## C. 訂單編號反查與分色

**反查（匯入時）**：
- `parseExcelFile` 先掃描所有 sheet，找含「訂單編號」與「房型房號/房間房號」標題的 sheet。
- 從該 sheet 建 `orderIdMap`：房號 → 訂單編號（房號由「房型房號」格抽開頭數字，一格多房以 `/` 分隔逐一建立）。
- 套用到解析結果（新訂單與 8 欄均適用）：`room.orderId = orderIdMap[roomNumber]`。
- `parseOrderMatrix` 現有邏輯保留並擴充輸出 `orderId`。
- `sanitizeRooms` 保留 `orderId`（既有資料無則為空）。

**分色（渲染時）**：
- 分組 key 優先 `orderId`，否則退回 `source`。
- 以排序後第一次出現順序，依 8 色色盤依序賦色（穩定，重繪不跳色）。
- 用該列**下緣邊線（border-bottom）色帶**標示，不與藍底（已用餐）、黃框（加購）衝突。
- `core.js` 純函式：`assignGroupColors(rooms, palette)` 回傳 `Map<roomNumber, color>`。

## D. 統計修正

`computeStats`（兩個模式一致）：
- `hot`（熟食）= `isHotRoom(r)` 數量（含加購）
- `normal`（平台）= `isPlatformRoom(r)` 數量 → 熟食＋平台 = 總數
- `addon` = `isAddon(r)` 數量（為熟食子集，供加購收費追蹤）
- `completed/pending/total` 同現況

> ⚠️ 此項會讓「熟食」卡片的數字比現況略增（加購房計入熟食），與左欄「熟食」對應。

**警示橫幅（熟食未用餐）**：
- 熟食區所有房中，`getStatus === PENDING` 且 `mealTime !== '不用餐'` 的數量。
- 新訂單、8 欄、卡片三種模式統一套用。

## E. 早餐用餐時間

### 資料結構

```js
settings: {
  types: [...],        // 既有
  prep: {...},         // 既有（備料區）
  mealSlots: [         // 新增
    { label: '8:15', enabled: true },
    { label: '9:30', enabled: false }
  ]
}
```

- 預設 `[]`。新增去重、不留空label。啟用狀態常駐。
- 每房 `mealTime`（沿用現有欄位）：時段文字或 `'不用餐'`；「清除」＝ `''`。
- 不引入 dailyMealSlots／每房每日 noMeal（取代舊設計 E）。

### 設定區 UI

- 功能選單新增 `🍳 早餐用餐時間`（放「備料區」下方）→ `mealSlotsModal`：
  - 輸入框（placeholder「例如 8:15」）＋「新增」
  - 列表：checkbox（enabled）＋ label ＋ ✕ 刪除
  - 空列表提示「尚未設定時段」
  - 「完成」關閉

### 主頁面時間欄（更改欄）

- 新訂單與 8 欄網格「時間」格 `data-timeset` 可點，`stopPropagation` 不觸發整列切換。
- 點擊 → `timePickerModal`：
  - 標題：房號 XXX 用餐時間
  - 啟用的時段大按鈕（每格一個）
  - 「不用餐」灰色按鈕、「清除（空白）」
  - 無啟用時段時顯示「尚未設定時段，請先到選單設定」
- 選定 → `room.mealTime = 值`、`saveState()`、`renderGrid(tk)`、toast。
- 新訂單「改」按鈕（完整 orderEditModal）與其內時間輸入框保留。
